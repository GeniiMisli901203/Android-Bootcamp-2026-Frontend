# Техническое задание на разработку программного продукта для планирования встреч
## Команда: Undigital Android


## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.


## User Stories

1. **Как** сотрудник компании,  
   **я хочу** видеть свой текущий профиль (ФИО, должность, отдел, контакты) в интерфейсе продукта,  
   **чтобы** убедиться, что данные актуальны и корректны.  

2. **Как** сотрудник,  
   **я хочу** редактировать основные поля своего профиля (например, телефон, email, должность),  
   **чтобы** оперативно исправлять ошибки или обновлять информацию при изменениях.  

3. **Как** сотрудник,  
   **я хочу** загружать и менять фото в профиле,  
   **чтобы** другие коллеги могли меня легко узнавать на встречах.  

4. **Как** сотрудник,  
   **я хочу** указывать свои рабочие часы и дни доступности в профиле,  
   **чтобы** коллеги при планировании встреч видели, когда я свободен.  

5. **Как** сотрудник,  
   **я хочу** добавлять в профиль краткую самопрезентацию или ключевые навыки,  
   **чтобы** участники встреч могли лучше понять мою роль и экспертизу.  

6. **Как** сотрудник,  
   **я хочу** просматривать историю изменений своего профиля (кто и когда вносил правки),  
   **чтобы** отслеживать корректность данных и выявлять возможные ошибки.  

7. **Как** сотрудник,  
   **я хочу** получать уведомление при автоматическом обновлении данных профиля (например, из HR‑системы),  
   **чтобы** быть в курсе изменений и вовремя реагировать на неточности.  

8. **Как** сотрудник,  
   **я хочу** временно скрывать некоторые поля профиля (например, контактный телефон) от коллег,  
   **чтобы** контролировать уровень доступности вне рабочих задач.  

9. **Как** сотрудник,  
   **я хочу** связывать свой профиль с корпоративными системами (например, CRM или таск‑трекером),  
   **чтобы** данные синхронизировались автоматически и не приходилось вводить их вручную.  

10. **Как** сотрудник,  
    **я хочу** иметь возможность запросить помощь техподдержки через интерфейс профиля,  
    **чтобы** быстро решать проблемы с данными, если не получается исправить их самостоятельно.


## Use Cases:

### 1. Просмотр профиля пользователя
**Акторы:** сотрудник, система.  
**Предусловия:**  
- сотрудник авторизован в системе;  
- профиль сотрудника существует в базе данных.  
**Основной сценарий:**  
1. Сотрудник открывает раздел «Мой профиль».  
2. Система отображает ФИО, должность, отдел, контакты и фото.  
3. Сотрудник просматривает данные.  
**Альтернативные сценарии:**  
- Если данные неполные: система показывает заглушки («Не указано») для отсутствующих полей.  
- Если фото не загружено: отображается иконка-заполнитель.  
**Постусловия:** сотрудник ознакомился с текущими данными профиля.  
**Исключения:**  
- Ошибка загрузки данных: система показывает сообщение «Не удалось загрузить профиль. Попробуйте позже».  
- Таймаут запроса: система предлагает повторить попытку.  

### 2. Редактирование основных полей профиля
**Акторы:** сотрудник, система.  
**Предусловия:**  
- сотрудник авторизован;  
- профиль открыт в режиме просмотра.  
**Основной сценарий:**  
1. Сотрудник нажимает кнопку «Редактировать».  
2. Система открывает форму с полями: ФИО, должность, телефон, email.  
3. Сотрудник вносит изменения.  
4. Сотрудник нажимает «Сохранить».  
5. Система валидирует данные (проверка формата email, длины телефона).  
6. Система сохраняет изменения и отображает обновлённый профиль.  
**Альтернативные сценарии:**  
- При ошибке валидации: система выделяет некорректные поля и показывает подсказки.  
- Отмена редактирования: сотрудник нажимает «Отмена», система возвращает к режиму просмотра.  
**Постусловия:** данные профиля обновлены.  
**Исключения:**  
- Конфликт версий: если данные изменились в другой сессии, система просит перезагрузить профиль.  
- Серверная ошибка: сообщение «Не удалось сохранить изменения. Повторите попытку».  

### 3. Загрузка/замена фото профиля
**Акторы:** сотрудник, система.  
**Предусловия:** сотрудник авторизован.  
**Основной сценарий:**  
1. Сотрудник переходит в настройки профиля.  
2. Нажимает иконку камеры или «Загрузить фото».  
3. Система открывает диалог выбора файла (ограничение: JPG/PNG, до 2 МБ).  
4. Сотрудник выбирает файл.  
5. Система отображает превью.  
6. Сотрудник подтверждает загрузку.  
7. Система сохраняет фото и обновляет профиль.  
**Альтернативные сценарии:**  
- Неподходящий формат: система показывает ошибку «Допустимы JPG/PNG».  
- Превышение размера: сообщение «Файл слишком большой (максимум 2 МБ)».  
**Постусловия:** фото профиля обновлено.  
**Исключения:**  
- Ошибка загрузки: система предлагает повторить попытку.  

### 4. Указание рабочих часов и доступности
**Акторы:** сотрудник, система.  
**Предусловия:** сотрудник авторизован.  
**Основной сценарий:**  
1. Сотрудник открывает раздел «Доступность».  
2. Система отображает календарь с таймслотами.  
3. Сотрудник отмечает рабочие дни и часы.  
4. Нажимает «Сохранить».  
5. Система обновляет статус доступности для коллег.  
**Альтернативные сценарии:**  
- Сброс настроек: сотрудник выбирает «Очистить», система удаляет все таймслоты.  
- Частичное заполнение: система сохраняет только указанные интервалы.  
**Постусловия:** коллеги видят актуальные часы доступности сотрудника.  
**Исключения:**  
- Конфликт с корпоративным графиком: система предупреждает «Ваши часы противоречат общему расписанию отдела».  

### 5. Добавление самопрезентации/навыков
**Акторы:** сотрудник, система.  
**Предусловия:** сотрудник авторизован.  
**Основной сценарий:**  
1. Сотрудник переходит в «О себе».  
2. Система открывает текстовое поле и теги-подборщик навыков.  
3. Сотрудник вводит описание (до 500 знаков) и выбирает навыки из списка.  
4. Нажимает «Применить».  
5. Система сохраняет данные и отображает их в профиле.  
**Альтернативные сценарии:**  
- Очистка поля: сотрудник удаляет текст, система сохраняет пустое значение.  
- Лимит символов: при превышении система обрезает текст и показывает уведомление.  
**Постусловия:** описание и навыки видны другим пользователям.  
**Исключения:**  
- Ошибка сохранения: сообщение «Не удалось обновить данные. Попробуйте ещё раз».  

### 6. Просмотр истории изменений профиля

**Акторы:** сотрудник, система.  
**Предусловия:** сотрудник авторизован.  
**Основной сценарий:**  
1. Сотрудник открывает «Историю изменений».  
2. Система отображает таблицу: дата, поле, старое/новое значение, инициатор (система/пользователь).  
3. Сотрудник изучает записи.  
**Альтернативные сценарии:**  
- Пустая история: система показывает «Нет записей об изменениях».  
- Фильтрация: сотрудник выбирает период, система обновляет таблицу.  
**Постусловия:** сотрудник ознакомлен с историей правок.  

**Исключения:**  
- Ошибка загрузки: сообщение «Не удалось получить историю. Повторите запрос».  

### 7. Получение уведомлений об автоматическом обновлении
**Акторы:** система, сотрудник.  
**Предусловия:**  
- включены уведомления;  
- произошло автоматическое обновление данных (например, из HR‑системы).  
**Основной сценарий:**  
1. Система фиксирует изменение данных.  
2. Отправляет push‑уведомление или email: «Ваш профиль обновлён: [поле] → [новое значение]».  
3. Сотрудник открывает уведомление.  
4. Система перенаправляет в профиль для проверки.  
**Альтернативные сценарии:**  
- Отключённые уведомления: система не отправляет сообщение.  
- Ошибка отправки: логирование события без оповещения.  
**Постусловия:** сотрудник проинформирован об изменениях.  
**Исключения:**  
- Ложное срабатывание: система не отправляет уведомление при тестовых изменениях.  

### 8. Скрытие полей профиля от коллег
**Акторы:** сотрудник, система.  
**Предусловия:** сотрудник авторизован.  
**Основной сценарий:**  
1. Сотрудник открывает настройки приватности.  
2. Система отображает список полей (телефон, email, отдел).  
3. Сотрудник снимает галочки с нужных полей.  
4. Нажимает «Сохранить».  
5. Система применяет настройки: скрытые поля не видны другим.  
**Альтернативные сценарии:**  
- Возврат видимости: сотрудник ставит галочки, система отображает поля.  
- Сброс до дефолта: кнопка «Сбросить», система восстанавливает исходные настройки.  
**Постусловия:** приватность профиля обновлена.  
**Исключения:**  
- Ограниченные права: система показывает «Некоторые поля нельзя скрыть».  

### 9. Синхронизация профиля с корпоративными системами
**Акторы:** сотрудник, система, HR‑система/CRM.  
**Предусловия:**  
- сотрудник авторизован;  
- интеграция с внешними системами настроена.  
**Основной сценарий:**  
1. Сотрудник открывает «Интеграции».  
2. Система показывает список подключённых сервисов (HR, CRM).  
3. Сотрудник выбирает систему и нажимает «Синхронизировать».  
4. Система запрашивает данные из внешней системы.  
5. Отображает превью изменений.  
6. Сотрудник подтверждает синхронизацию.  
7. Система обновляет профиль и показывает статус «Синхронизировано».  
**Альтернативные сценарии:**  
- Отсутствие данных: система сообщает «Нет данных для синхронизации».  
- Конфликт данных: система предлагает выбрать приоритет (локальные/внешние).  
**Постусловия:** профиль синхронизирован с внешней системой.  
**Исключения:**  
- Ошибка подключения: сообщение «Не удалось подключиться к системе. Проверьте настройки».  

### 10. Обращение в техподдержку через профиль
**Акторы:** сотрудник, система, оператор поддержки.  
**Предусловия:** сотрудник авторизован.  
**Основной сценарий:**  
1. Сотрудник открывает «Помощь» в профиле.  
2. Система отображает форму: тема, описание, вложение (опционально).  
3. Сотрудник заполняет поля и прикрепляет скриншот (если нужно).  
4. Нажимает «Отправить».  
5. Система отправляет запрос и показывает номер обращения.  
6. Оператор получает заявку и отвечает в течение 24 часов.  
**Альтернативные сценарии:**  
- Незаполненные поля: система выделяет обязательные поля красным.  
- Отмена: сотрудник закрывает форму, запрос не отправляется.  

**Постусловия:** заявка зарегистрирована, сотрудник получит ответ.  
**Исключения:**  
- Ошибка отправки: система предлагает сохранить черновик или повторить попытку.



## Набор задач для Frontend

#### 1. Реализация авторизации и регистрации
- Разработать экраны:
  - входа (email/пароль);
  - регистрации (email, пароль, подтверждение пароля, ФИО);
  - восстановления пароля.
- Реализовать валидацию полей:
  - формат email;
  - минимальная длина пароля (8 символов);
  - совпадение паролей при регистрации.
- Добавить обработку ошибок (неверный логин/пароль, существующий email).
- Обеспечить сохранение сессии после авторизации.

#### 2. Разработка интерфейса личного профиля
- Создать экран просмотра профиля с полями:
  - ФИО;
  - должность;
  - отдел;
  - email и телефон;
  - фото профиля (заполнитель при отсутствии).
- Реализовать кнопку «Редактировать» с переходом на форму изменений.
- Обеспечить адаптивность под разные размеры экранов (смартфоны, планшеты).

#### 3. Форма редактирования профиля
- Разработать форму с полями:
  - ФИО (валидация: не менее 2 слов);
  - должность (выпадающий список из предустановленных значений);
  - email (проверка формата);
  - телефон (маска ввода).
- Добавить:
  - кнопку «Сохранить» (активируется при валидных данных);
  - кнопку «Отмена».
- Реализовать мгновенную валидацию с подсказками.

#### 4. Загрузка фото профиля
- Реализовать компонент выбора изображения (поддержка JPG/PNG).
- Ограничить размер файла до 2 МБ.
- Добавить превью перед загрузкой.
- Обеспечить отображение ошибок:
  - неверный формат;
  - превышение размера.
- Сохранить изображение в профиле после подтверждения.

#### 5. Создание встречи
- Разработать экран создания встречи с полями:
  - название;
  - дата (календарь);
  - время (выбор из часовых слотов: 9:00, 10:00 и т. д.);
  - продолжительность (1–4 часа с шагом в 1 час);
  - описание (опционально);
  - список приглашённых (поиск по ФИО/email).
- Добавить кнопку «Создать» с валидацией обязательных полей.
- Реализовать проверку доступности слотов (нельзя создать встречу на занятое время).

#### 6. Управление приглашениями на встречи
- Создать экран «Активные приглашения» со списком:
  - название встречи;
  - дата и время;
  - организатор.
- Для каждого приглашения добавить кнопки:
  - «Принять»;
  - «Отклонить».
- После ответа:
  - изменить статус приглашения;
  - отправить уведомление организатору.
- Реализовать фильтрацию: «Неотвеченные», «Принятые», «Отклонённые».

#### 7. Просмотр расписания встреч
- Разработать три режима отображения:
  - **День**: список встреч по часам (9:00–10:00, 10:00–11:00 и т. д.).
  - **Неделя**: календарь с цветовыми маркерами встреч.
  - **Месяц**: мини‑календарь с точками-индикаторами дней с событиями.
- Для каждой встречи отображать:
  - название;
  - время;
  - участников.
- Добавить возможность перехода к деталям встречи.

#### 8. Детали встречи
- Создать экран с полной информацией:
  - название, дата, время;
  - организатор;
  - список участников с статусами («Принял», «Отклонил», «Ожидает»);
  - описание.
- Добавить кнопку «Выйти из встречи» (для участника).
- Для организатора: кнопка «Отменить встречу» с оповещением участников.

#### 9. Уведомления
- Реализовать локальные уведомления:
  - о новых приглашениях;
  - напоминания за 15 мин до встречи.
- Добавить настройки уведомлений в профиле (включение/выключение типов).
- Обеспечить переход в детали встречи при клике на уведомление.

#### 10. Общие требования к интерфейсу
- Использовать **Kotlin** (предпочтительно) или **Java**.
- Применить **ConstraintLayout/LinearLayout** для адаптивной вёрстки.
- Соблюдать **Material Design 3** (цвета, типографика, отступы).
- Обеспечить **доступность**:
  - контрастность элементов;
  - поддержка TalkBack.
- Оптимизировать производительность:
  - ленивая загрузка изображений;
  - кэширование данных.
- Протестировать на устройствах с разными версиями Android (min API 21).
